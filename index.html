Work at the right level

This tool mirrors two billable dimensions: cMAU (attribute by application via application.id) and service connections (attribute by project / environment). Raw project totals alone are not enough for chargeback — use the tabs for attribution tables and allocation.

  • cMAU — Registered apps, per-application cMAU share, environment gap report, MAU by SDK type
  • Connections — Stream mix (server / browser / mobile) and each project’s share of org connection peaks
  • Capacity — Utilization vs optional contracted ceilings (70% / 90% guides)
  • Trends — Time series, project cards, and CSV export for analysis

cMAU billing by application primary context

Month-to-date billed cMAU per application as reported by LD on the snapshot day (—). Primary context kind only. Cost share ≈ entity cMAU ÷ org cMAU. Application attribution needs SDKs sending application.id; per-project sums environment-level cMAU.

⚠ cMAU counts unique contexts. A context active in more than one application (or project) is counted in each, so per-entity cMAU can sum to more than the billed org total — these are proportional allocations, not a clean de-duplicated split. The org total reconciles to the invoice; the per-entity breakdown does not.

Largest context kind by application proportional

Each application sized by its single largest context kind (client-side context usage across all kinds, from /usage/clientside-contexts), allocated proportionally against the sum of those maxima. De-duplicated relative comparison — LaunchDarkly increasingly bills on the highest-cardinality kind, so this tracks the billing-relevant dimension rather than the primary-context figure above.

Client MAU Over Time

Running total of daily unique-user counts. Approximation — users active on multiple days are counted on each. Not the billed figure (LD bills on the rolling 30-day peak; see Capacity panel).
